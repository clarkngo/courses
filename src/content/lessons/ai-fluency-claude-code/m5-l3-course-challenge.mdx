## How the Challenge Works

The challenge has two parts:

1. **Knowledge check:** ten scenario questions covering every module. Aim for at least 8 out of 10. If you miss one, read the explanation and revisit that lesson.
2. **Capstone task:** take one real task from your own work through all four Ds with Claude Code, and keep a short log as you go.

This course is free and self-paced, so there's nothing to submit. The goal is a way of working with agents that lasts longer than any particular feature.

## Part 2: Capstone, One Task Through the 4Ds

Choose a real, medium-sized task from your own work: a bug with a reproducible failure, a small feature, or a refactor of one module. Keep a short log in a text file as you go.

<TryIt title="Delegation: Decide and Set the Dial">

1. Write the task in one sentence.
2. Answer the three delegation questions: Is it verifiable? Is it sized for review? Is a mistake reversible?
3. Decide which parts you'll delegate, which you'll do together (augmentation), and which you'll keep.
4. Choose a permission mode and any allow, ask, or deny rules for this task. Write down why.
5. Create a branch (or worktree) and confirm a clean git state.

</TryIt>

<TryIt title="Description: Brief It">

1. Check that your CLAUDE.md has the exact test and lint commands. Update it if not.
2. Write a four-part brief: goal, context (with `@` file references), constraints, and done.
3. Start in plan mode. Review the plan with the Stage 1 questions from module 4 and push back at least once if anything is off.
4. Log what you changed in the plan and why.

</TryIt>

<TryIt title="Discernment: Review Like You Mean It">

1. Let the agent execute. Interrupt if it drifts, and log each interruption.
2. When it finishes, run `git diff --stat` before reading its summary.
3. Read the full diff and check it against the failure-mode field guide from module 4.
4. Run the key verification yourself.
5. Ask a fresh session to review the diff skeptically. Log anything it found that you didn't.

</TryIt>

<TryIt title="Diligence: Ship It Responsibly">

1. Run your personal shipping checklist from the last lesson.
2. Scan the diff for secrets, debug output, and unrelated changes.
3. Pass the explain-it test for the riskiest part, or rework that part until you do.
4. Open a small pull request with a human-written note on why the change is right and what was AI-assisted, following your team's norms.
5. Finish your log with one paragraph: what you'd do differently next time, and one line to add to your CLAUDE.md or standard brief.

</TryIt>
