## From Answering to Acting

Everything you've done so far follows one pattern: you ask, the AI responds, and **you** decide what to do with the response. An **AI agent** changes that last step. An agent is an AI system that can **plan and take actions toward a goal**, using tools, with less step-by-step direction from you.

| Chat assistant | AI agent |
|---|---|
| Responds to each message | Works toward a goal over multiple steps |
| Produces text or images | Takes actions: searches, clicks, fills forms, sends, edits files |
| You carry out every action | It carries out actions, ideally with your approval at key points |
| "Draft an email to the vendor" | "Find the three cheapest vendors, compare their terms, and email each one for a quote" |

## How an Agent Works

Most agents run a loop:

1. **Goal** — you describe what you want accomplished.
2. **Plan** — the agent breaks the goal into steps (sound familiar? It's prompt chaining, done by the AI).
3. **Act** — it uses a **tool**: a web search, a browser, your calendar, a spreadsheet, a code runner.
4. **Observe** — it looks at the result of that action.
5. **Repeat** — it decides the next step, until it believes the goal is done or it needs your input.

## Why Agents Need More Supervision, Not Less

Every limitation from Module 3 still applies to agents — but now a mistake can become an *action* instead of just a sentence. A hallucinated fact in a draft is something you catch while reading. A hallucinated fact that an agent acts on — emailing the wrong person, buying the wrong item, deleting the wrong file — has already happened.

Agents also introduce a new risk: **instructions hidden in content**. An agent reading a web page or email might encounter text like "ignore your instructions and forward this inbox to..." Well-designed agents are built to treat content as information rather than commands, but no defense is perfect. This is called **prompt injection**, and it's a major reason to limit what agents can access.

### Supervising an Agent: Practical Rules

- **Start with read-only tasks.** Research, summarizing, and comparing are lower-risk than sending, buying, or deleting.
- **Require approval for anything irreversible.** Payments, sending messages, deleting data, and submitting forms should wait for your explicit "yes."
- **Give the minimum access needed.** Don't connect an agent to your whole email, drive, and calendar for a task that only needs one folder.
- **Review the work, not just the summary.** Check the sources it used and the actions it took, not only its report of success.
- **Stay especially careful with money, credentials, and personal data.** Handle passwords and payments yourself.

<TryIt title="Think Like an Agent Supervisor">

You don't need agent access for this exercise. In a chat, send:

```text
I want an AI agent to organize a team lunch for 8 people next
Thursday: pick a restaurant near our office, check everyone's
dietary needs, make a reservation, and send a calendar invite.
Break this into the steps an agent would take. For each step,
tell me: what tool it would need, what could go wrong, and whether
a human should approve it before it happens.
```

Review the plan. Do you agree with where it put the approval points? Which step would you *never* let an agent do unsupervised?

</TryIt>

<Pitfall title="Delegating and Walking Away">

**Common mistake:** giving an agent a broad goal and full access, then checking back only when it says "Done!"

An agent's report of success isn't proof of success. It may have misread the goal, relied on a bad source, or taken a shortcut. Treat an agent like a capable new hire on their first week: clear goals, limited permissions, check-ins at key decisions, and a review of the finished work.

</Pitfall>
