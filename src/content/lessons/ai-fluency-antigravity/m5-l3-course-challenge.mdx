## How the Challenge Works

The challenge has two parts:

1. **Knowledge check:** ten scenario questions covering every module. Aim for at least 8 out of 10. If you miss one, read the explanation and revisit that lesson.
2. **Capstone task:** run two parallel agents on real work, plus one read-only automation, and take everything through the 4Ds. Keep a short log as you go.

This course is free and self-paced, so there's nothing to submit.

## Part 2: Capstone, A Small Fleet Through the 4Ds

Pick a project you work on. You'll run **two parallel agents** on independent tasks and set up **one read-only automation**.

<TryIt title="Delegation: Plan the Fleet">

1. Choose two real tasks that touch different files and share no undecided design choices. Write why they're independent.
2. Choose one read-only automation, such as a daily test-run summary or a weekly dependency audit.
3. For each, answer: verifiable? sized for review? reversible?
4. Set a permission preset for the project, plus at least three allow, two ask, and two deny rules.
5. Confirm a clean git state and that non-workspace file access is off.

</TryIt>

<TryIt title="Description: Brief the Fleet">

1. Check that your AGENTS.md has exact commands, conventions, and a "when blocked" rule.
2. Write a four-part brief for each agent, including what evidence the walkthrough must show and, for UI work, which browser checks to record.
3. Choose a model and thinking level for each agent and for the automation, with one sentence on why.
4. Start both agents in Planning mode. Leave at least two inline comments on each plan before approving.

</TryIt>

<TryIt title="Discernment: Review Like a Lead">

1. For each agent, read the **diff first**, then the walkthrough. Mark each walkthrough claim as verified, unverified, or wrong.
2. Check each diff against the failure modes: scope creep, weakened tests, new dependencies, swallowed errors.
3. For any browser evidence, write what it proves and what it doesn't. Do one manual click-through yourself.
4. Have a fresh agent on a different model review the riskier of the two diffs. Log what it found.

</TryIt>

<TryIt title="Diligence: Ship and Own It">

1. Run your merge checklist from the last lesson on each change.
2. Merge only what passes. Note anything you held back and why.
3. Give the automation an owner (you), a purpose, and a review date, and check your overage setting.
4. Disclose AI assistance according to your team's or project's norms.
5. Finish your log: how many agents you could review well, one line to add to AGENTS.md, and one thing you'd change about your permission rules.

</TryIt>
